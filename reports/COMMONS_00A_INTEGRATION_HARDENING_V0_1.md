## 2. Publication-path nonconformity (organization registry)

The organization's private registry repository has a mandatory pre-merge
publication gate. A governed work-order pull request must carry an
authoritative evidence block, and its `Repository Integrity` run must pass
before merge. Neither 00A registry pull request satisfied that gate:

| PR | Head | Merge | PR-context gate run | What happened |
| --- | --- | --- | --- | --- |
| #317 pointer | `af085b1d` | `01f10752` (17:42:39Z) | 37141162018: failure, `AUTHORITATIVE_BLOCK_MISSING` (merge-blocking) | The gate had already failed when the PR was merged. |
| #318 closure | `2456841d` | `6dc5c103` (17:43:08Z) | 37141541394: failure, `AUTHORITATIVE_BLOCK_MISSING` (merge-blocking) | Merged one second before the gate run started; the run then failed. |

Classification: **COMMONS_SYSTEMS_PUBLICATION_PATH_NONCONFORMITY**.

Root cause: the 00A executor checked only the registry's graph, sensitive-path
and claims-ledger scripts and a local test suite. It did not check the PR's
own hosted `Repository Integrity` status before merging.

This concerns the registry's merge ceremony only. It does not show that Commons
contains private code, that its clean history or review failed, or that the
schemas, the lint, public CI or provenance failed. The historical runs remain
failures and are recorded as failures. The repair is carried out in the
registry by a separate, gate-conformant pull request under this work order.

## 4. Public-provenance sanity check (WO §20)

The 00A reviewer's 63 probe inputs (`probe.py`, `probe2.py`, `probe3.py`) were
rerun against the 00B candidate tree.

| Constraint | Result |
| --- | --- |
| Private repository locators (org slug, host paths, remotes, URLs, short and long commit IDs) | All probe classes that were blocking in 00A are rejected |
| Absolute private filesystem locators (`/home`, `/tmp`, `/etc`, `~`, backtick, `\|`, `>`, colon-prefixed, fullwidth) | Rejected |
| Personal identity where a role token is required | Rejected (schema + `PERSONAL_DATA`) |
| Undeclared schema fields | Rejected (all objects closed; T10) |
| Unknown release class | Rejected (INVALID-06) |
| Unresolved clearance state | Rejected (T2, INVALID-09) |

Of the 63 probes, 18 cover the formerly blocking classes, and all 18 are
rejected. 22 still pass:

- the 2 valid baselines;
- 20 inputs that were already disclosed as known limits in 00A: plain project
  names, other organizations' slugs, all-digit hex runs, homoglyphs,
  role-shaped personal handles, non-US phone formats, policy-level license and
  strategic-review content, and relative paths.

There are no regressions. The new closure receipt is checked by
`test_nc7_closure_receipt_exposes_no_private_locator_or_personal_data`, which
applies every locator and personal-data rule except the commit-ID rule, since
the receipt binds commit IDs on purpose. Its power is shown by four injected
leak cases.

These checks do not prove that no sensitive data exists anywhere.
